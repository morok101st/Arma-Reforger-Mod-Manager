# ARMM 1.0.0

## Changes

- The mod sidebar shows the running ARMM version and a link to the GitHub repository. The account menu provides the same information on pages without the sidebar.
- Administrators on a stable build see a link to the release notes when GitHub has a newer stable ARMM release. ARMM checks for updates without installing them automatically.
- The Sync access **More actions** menu groups Edit, Download, Disable and Delete. Deleting an access invalidates its existing sync key and app configurations while preserving the modset and its mods.
- Updated Python, Node.js, Nginx and application dependencies, including PyJWT and cryptography security fixes. Dependabot is configured for dependency maintenance.

## Upgrade from 0.2.8

Back up PostgreSQL and the matching `.env`. Keep the existing data volume and `ARMM_SECRET_KEY`, set `ARMM_IMAGE_TAG=1.0.0`, and pull and recreate the ARMM services. There is no new database migration, service, or required environment variable. Existing sync accesses remain valid unless an administrator deletes, disables, or replaces them.

After upgrading, check application health, sign in and verify an existing Sync export if your deployment uses Sync access. For earlier versions, review the [upgrade guide](https://github.com/morok101st/Arma-Reforger-Mod-Manager/blob/v1.0.0/docs/upgrading.md).
