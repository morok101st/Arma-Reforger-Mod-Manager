## Changes since 0.2.5

- Redesign the workspace, mod details, modset management and administration with clearer navigation, neutral dark surfaces and consistent controls.
- Improve mobile layouts, keyboard navigation, dialogs, dropdowns and retained form drafts after failures.
- Distinguish loading, empty data and failed reads; retry reads without repeating successful writes.
- Clarify version health: No installed version remains neutral, while missing latest versions have their own category.
- Save user account, group membership and optional password changes atomically, rolling back the complete update on failure.
- Preserve selected views, modsets and mods through URLs, reloads, browser history and login redirects.
- Persist individual manual update checks across reloads and tabs, prevent duplicate checks for the same mod/modset, and allow retry after failure or interruption.
- Refresh README, wiki and guides with current screenshots, architecture diagrams and reproducible asset tooling.

## Upgrading from 0.2.5

Back up PostgreSQL and the matching `.env`, especially `ARMM_SECRET_KEY`. Allow active checks to finish, stop the old backend and update matching images to `0.2.6`. Keep existing data volumes and reload browser tabs after startup.

The additive `002_mod_refresh_jobs` migration runs automatically and preserves existing accounts, group grants, modsets, installed versions, export order, history and webhook selections. Existing 0.2.5 in-memory checks cannot be imported. No new required environment variables or additional service is needed. PostgreSQL job execution requires direct connections or session pooling, not transaction pooling.

Existing synchronous single-mod refresh responses and Discord links remain supported. Manual checks still do not emit Discord update alerts; scheduled notification rules are unchanged. Global Shared access was already removed in 0.2.5, not in this release.

See the [upgrade guide](https://github.com/morok101st/Arma-Reforger-Mod-Manager/blob/v0.2.6/docs/upgrading.md). For rollback, restore the matching pre-upgrade database backup, `.env` and old images with backends stopped; changes after the backup are lost.
