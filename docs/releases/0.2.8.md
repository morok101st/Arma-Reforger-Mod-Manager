# ARMM 0.2.8

## Changes

- **Sync access:** administrators configure one export-only access per modset through a wizard. Only configured accesses appear as rows, with saved name/connection details, status, edit, download and disable actions. Normal users keep their existing session-authenticated API permissions.
- Import `armm-sync.json` in a compatible sync app. It includes `baseUrl`, `modsetId`, server-generated `exportPath` and a scoped key, plus optional game server host/port/`passwordRequired`. Actual game server passwords are never stored. Repeated downloads reuse the encrypted stored key; replacement is explicit and revokes old configurations.
- Child sync exports include inherited binding versions and effective export order. Creator/admin authority is checked on every export; parent changes disable the access. Keys cannot modify data or access other modsets.
- **Estimated size:** Overview sums installed local/inherited/dependency Workshop sizes once per ID. Unknown sizes are identified and partial totals are labeled; the estimate is not measured disk usage.
- Workshop size extraction uses structured metadata instead of description prose and repairs invalid cached sizes during successful refreshes.
- Up/Down navigates the displayed mod list, the overview action uses a home icon, and size explanations appear on hover/focus. Modset Edit/Export/Duplicate/Delete actions share one menu with correct active-row normal/hover states.

## Upgrade from 0.2.7

Back up PostgreSQL and the matching `.env`, especially `ARMM_SECRET_KEY`, and verify a restore. Let checks finish, stop the old backend before the final backup, then update all ARMM images to `0.2.8`, keeping existing volumes. Do not run old/new backends together.

Startup automatically applies additive, retryable migrations `005_modset_sync_access` and `006_sync_configuration`. Existing modsets, installed versions, parent/child order, groups/grants, sessions and exports are preserved. No new service or required environment variable is introduced. Sync access is optional and initially empty for 0.2.7 installations. Existing session-based integrations remain compatible.

If upgrading from an earlier development build, existing access hashes are retained. Finish setup to save settings and restore a recoverable key, or explicitly replace it. Old non-admin-created accesses remain blocked until an active administrator renews them.

Keep `ARMM_SECRET_KEY` unchanged: it is needed to recover encrypted webhooks and sync keys. After startup, inspect health/logs, reload browser tabs and compare a known export. Direct 0.2.7 upgrades are regression-tested on SQLite and PostgreSQL, including inherited exports and group access.

For rollback, stop the backend and restore the matching pre-upgrade database, `.env` and old images. Changes after the backup are lost; application-only downgrade against the expanded schema is not certified.

See the [upgrade guide](https://github.com/morok101st/Arma-Reforger-Mod-Manager/blob/v0.2.8/docs/upgrading.md) and [Sync access guide](https://github.com/morok101st/Arma-Reforger-Mod-Manager/blob/v0.2.8/docs/sync-access.md).
