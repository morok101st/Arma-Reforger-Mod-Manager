## Upgrade notice: global Shared access has been removed

Previously shared modsets are no longer available to every signed-in user. Owners and administrators retain access; other users and service accounts need explicit group permissions. No replacement all-users group is created automatically.

Back up the database and matching `.env` before upgrading. The database upgrade is additive and preserves existing data and webhook selections. Historical `shared` values remain stored for compatibility but no longer grant access. Accounts, modsets, installed versions, export order, history, and existing group grants are retained. Administrators have emergency access to every modset without taking ownership.

After upgrading, create groups in **Security → Groups**, assign users, and configure Read or Write under **Modsets → Edit → Group access**. Verify service-account access before reopening the instance. Service accounts continue to authenticate using session cookies; API tokens are not included in this release.

See the [upgrade and recovery guide](https://github.com/morok101st/Arma-Reforger-Mod-Manager/blob/v0.2.5/docs/group-sharing-upgrade.md).

## Changes

- Add administrator-managed groups and user memberships.
- Grant groups Read or Write access to selected modsets, with server-side permission checks and audit events.
- Integrate group permissions into the modset editor; save name and permissions in a single transaction.
- Give administrators full emergency access to user-owned modsets while preserving ownership.
- Preserve explicit and empty Discord webhook modset selections across backend restarts.
- Restrict manual bulk refresh to the selected authorized modset; scheduled checks continue to cover all modsets.
- Add versioned transactional group migrations and PostgreSQL/SQLite upgrade regression tests based on the frozen 0.2.4 schema.
