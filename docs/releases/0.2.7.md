# ARMM 0.2.7

## Changes

- Parent/child modsets share binding installed versions, including No installed version, with one inheritance level. Children can add their own mods. Parent read access remains required for child access and API exports.
- Follow parent export order while inserting local mods, or retain independent ordering. Parent edits update child exports; mode changes preview their effects. Detach and duplicate preserve effective snapshots.
- Export order uses consecutive positions and movement controls instead of numeric inputs. Existing numeric API endpoints remain compatible; the new sequence endpoint validates complete lists.
- Inherited entries use a consistent source icon. Child mods first is enabled by default, with the selected browser sort applied within each group; export order is unaffected.
- Dependency protection, persistent checks, activity feeds and scoped Discord notifications include inherited mods. Manual checks do not send notifications.

## Upgrade from 0.2.6

Back up PostgreSQL and the matching `.env`, especially `ARMM_SECRET_KEY`, and verify a restore. Allow checks to finish and stop the old backend before the final backup. Update matching ARMM images to `0.2.7`, retaining database and Reforger volumes. Do not run old/new backends together.

Startup automatically applies additive, retryable migrations `003_base_modsets` and `004_base_export_order`. Existing modsets, installed versions and numeric order values remain intact; existing modsets keep independent order. New child modsets default to following parent order. Physical legacy column names are intentionally retained. No new environment variables or services are required.

Inspect startup logs and health, reload browser tabs, compare a known export, and verify login/group access and parent/child behavior. A child grant does not grant parent access: share the parent separately. Nested inheritance is not supported.

For rollback, stop backends and restore the matching pre-upgrade database, configuration and old images. Changes since the backup are lost; application-only downgrade after using inheritance is not supported.

See the [upgrade guide](https://github.com/morok101st/Arma-Reforger-Mod-Manager/blob/v0.2.7/docs/upgrading.md) and [Parent/Child guide](https://github.com/morok101st/Arma-Reforger-Mod-Manager/blob/v0.2.7/docs/parent-child-modsets.md).
